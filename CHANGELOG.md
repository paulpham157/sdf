# Changelog

All notable changes to SDF will be documented in this file.

This file covers the first public release of the current product: a vendor-neutral OpenTelemetry (OTLP) collector for AI coding-agent telemetry, written in Go and stored in SQLite. It does not list the pre-rebuild Python/Herdr history. That tree is snapshotted at tag `legacy-v1` (commit `38f45e80ed05fd72e9387c2327d7fd7286bcfac3`, 2026-11-08 13:23 America/New_York).

## [Unreleased]

### Features

- Decision records take an optional `category` (`architecture`, `policy`, `product`, `implementation`, `operations`) ([#358](https://github.com/paulpham157/sdf/pull/358), [#362](https://github.com/paulpham157/sdf/pull/362)). `sdf decision list --category` filters by one of those tokens or by `none`, and the text table has a `CATEGORY` column. Unset is stored as SQL `NULL` and displayed as `implementation` in `sdf decision list`, the web UI, and as a missing `category` key on `GET /api/decisions`. `policy` requires `status` `decision`. `sdf decision check` does not read `category`. `decided_by` is a GitHub login (letters, digits, and single hyphens, at most 39 characters, no leading or trailing hyphen, no `--`). `user` and `agent` stay legal and display as legacy; existing rows are not rewritten. When `--decided-by` is omitted, sdf reads a login locally and does not use the network: `gh config get -h github.com user`, then `git config github.user` (every scope, including the repository; self-asserted attribution, not authentication). `git config user.name` is not read, and a configured `user` or `agent` is not stored. A missing `gh` does not fail the add. The lookup runs only after the rest of the record validates. The hosts.yml login takes precedence over `git config github.user`. `gh` has up to 3 seconds; if it hangs or fails, git still gets about 500ms, so the worst case is about 4.5 seconds (gh 3s, then git 0.5s, plus up to 0.5s for each killed command to close its pipes). Login badges stay within three characters so they fit the circle, the legend scrolls instead of covering nodes, and an empty decided_by tick uses the page background. Auto-resolution skips `user` and `agent` without regard to case. An explicit `--decided-by` keeps its exact case. There is no add-time warning that tries to tell a person from an agent. The recall harness accepts a login and still accepts `user` and `agent`; its skill-only baseline is unchanged. Known phase-1 gap: `isConstraint` in `internal/decision/brief/brief.go` still keys on the literal `user`, so a person-set rule is recorded with `--decided-by user` until a later spec amendment makes an active settled `policy` a constraint. A policy recorded with a login does not appear in the session-start brief and is not locked. `sdf decision check` still blocks by statement.
- The telemetry writer opened through `store.Open` uses SQLite `PRAGMA synchronous=NORMAL` when the file is in WAL mode, including a connection the pool opens to replace the writer. Under WAL with `NORMAL`, a power loss or an operating-system crash can lose the most recently committed transactions, and it does not corrupt the database. An application crash is safe. The setting is per connection, so readers keep `FULL`, and a file that is not in WAL mode keeps `FULL`. The ledger stays at `synchronous=FULL`. Ingest also prepares the records insert once, marshals attribute JSON outside the store lock, matches content keys without a prefix scan on every attribute, and decodes a gRPC export from the message the server already parsed ([#276](https://github.com/paulpham157/sdf/issues/276)).
- Restyle the local UI onto the shared design tokens ([#331](https://github.com/paulpham157/sdf/pull/331), [#332](https://github.com/paulpham157/sdf/pull/332)). The page serves a byte-identical copy of `design/tokens.css` at `/tokens.css` and links it before `app.css`. The header uses the woven-fabric mark, the route sets the document title, and colors, the decision graph, and the overview charts follow the token spec.
- `sdf hook stop --agent` reminds an agent once per session to record decisions that are not written down, and only when that session has an `sdf.git.commit` with no decision linked to the session or no `implements` edge. `sdf init --write` installs the Stop hook for Claude Code, Codex, Gemini (`AfterAgent`), Qwen, Grok, and Pi (`agent_before_settle`). The store is read-only; a missing or unreadable store lets the agent stop. `sdf decision list --session ID` filters to that session. Copilot and Cursor are spoken by the command and not installed (their hook files are not what `sdf init` writes). OpenCode has no Stop gate ([#285](https://github.com/paulpham157/sdf/issues/285)).
- Add a labeled recall harness (`internal/decision/recall`) and `sdf decision recall`. The harness ingests synthetic OTLP fixtures and scores decision recall, commit-link recall, and precision, with a 95% Wilson interval. CI gates on the measured skill-only baseline: both recalls are 0/labeled (7 decisions, 6 links) because SDF does not infer a decision, and precision is undefined. `sdf decision recall` reports link recall by proxy from `sdf decision audit` (`commits_linked / commits_in_decision_sessions`) on a read-only store. `--since` accepts a duration such as `24h` or RFC3339. Live-agent runs are not included ([#284](https://github.com/paulpham157/sdf/issues/284)).
- Auto-link a recorded git commit to a decision when `sdf.git.commit` arrives: if the commit's session already implements exactly one active decision, or if the commit carries one or more `SDF-Decision: <id>` trailers, append a `commit implements decision` edge. Unknown or retracted ids are rejected and logged (SHA and id only) and never create a ghost edge; a repeated event is idempotent. The post-commit hook reads and sends only `SDF-Decision` values, with `git log --format=%(trailers:key=SDF-Decision,valueonly)`, never the subject, body, other trailers, or the diff, and never `git interpret-trailers --parse`. A malformed id is dropped, is logged as invalid without the raw value, and does not fail the commit. The hook still does not write an `SDF-Decision` trailer. Re-run `sdf init --git-hooks` to replace a hook installed by an older sdf ([#281](https://github.com/paulpham157/sdf/issues/281), [#323](https://github.com/paulpham157/sdf/pull/323)).
- Serve the Software Decision Fabric mark as the UI favicon at `/favicon.svg` and `/favicon.ico` ([#321](https://github.com/paulpham157/sdf/pull/321)).
- The overview page plots decision-link recall over time, counts of unlinked commits and unlinked decisions (the same gaps `sdf decision audit` reports), and sessions plus computed cost by UTC day. `GET /api/overview-charts` builds the recall and gap series through `store.OpenReadOnly`, so it does not hold the writer's mutex. Session and cost series are `activity_by_day` on `GET /api/snapshot`. Charts are inline SVG with a data table; nothing is loaded from the network ([#316](https://github.com/paulpham157/sdf/issues/316), [#318](https://github.com/paulpham157/sdf/pull/318)).

### Fixes

- A finished gRPC export releases its in-flight byte reservation and its per-token slot before the status is written. The release used to run in another goroutine after gRPC had already cancelled the stream context, which it does before flushing the status. The next export could then be rejected with retryable `RESOURCE_EXHAUSTED` (`inflight limit` or `too many requests`) even though the previous call had succeeded, including an oversized message that should be `RESOURCE_EXHAUSTED` with no `RetryInfo`. A call that never reaches the handler still releases when its stream ends, and admission reaps that finished state before taking a new slot. An admitted header-only stream stays tracked until the connection closes or `--read-timeout` fires. A client cancel during the handler, including the SQLite commit, keeps the shrunk reservation and the token slot until the handler returns ([#354](https://github.com/paulpham157/sdf/pull/354)).
- A refused OTLP/HTTP request (403 or 401) no longer reserves the in-flight byte budget or allocates the body, so a large `Content-Length` with no body cannot crowd out an authenticated export. When a token is set, unauthenticated responses send `Connection: close`, and every keep-alive connection closes after 1000 requests or 10 minutes. An admitted gRPC call reserves its body from a share of at most half the in-flight budget (the whole budget when that budget is a single body) and keeps the reservation until the message arrives. `--read-timeout` cancels the call with `DEADLINE_EXCEEDED` and releases the reservation, including a header-only stream. With a token set, an unauthenticated gRPC client reserves nothing. Without a token, any local process can hold those reservations until the read timeout; loopback clients share one address, so the per-address cap does not separate them. The timer is stopped before the SQLite commit, and the reservation shrinks to the encoded size. Shutdown closes HTTP and UI connections that are still reading and lets a request that has started its commit finish and write 200. If gRPC graceful stop is still waiting after 2s, streams that are still reading are cancelled and a commit that has already started gets up to another 2s to write its status, then the remaining RPCs are closed. The whole wait is about 6s, so a header-only stream cannot hold the process. A second non-identity `Content-Encoding` is HTTP 415. A gRPC connection past the listener cap is closed with no bytes written. Request lines log the method and the path with Go's `%q`. `SDF_MAX_CONNS=0` and `-1` refuse to start, the same as the flags ([#271](https://github.com/paulpham157/sdf/issues/271)).
- Bound the OTLP/HTTP, OTLP/gRPC, and UI listeners so a client cannot hold connections or request bytes without limit. Each listener allows 128 concurrent connections, 64 from one address. Headers must arrive within 5s of the first byte (or of accept, for a new connection), a body within 30s, and a keep-alive connection goes idle after 90s. One body, including after gzip, stays capped at 8,000,000 bytes. In-flight bodies share 64 MiB. A body over the per-request cap is HTTP 413, or gRPC `RESOURCE_EXHAUSTED` with no retry hint. The connection cap is HTTP 503, one address over its cap is HTTP 429, and the byte and per-token caps are HTTP 503 or 429, each with `Retry-After: 1`. The same overload on an admitted gRPC stream is `RESOURCE_EXHAUSTED` with `RetryInfo` of one second. A success response is still sent only after the SQLite commit, with `partial_success` unset. Flags are `--max-conns`, `--max-conns-per-ip`, `--max-conns-per-token`, `--max-body-bytes`, `--max-inflight-bytes`, `--read-header-timeout`, `--read-timeout`, and `--idle-timeout`; the matching `SDF_*` variables are the fallback, and an invalid value refuses to start ([#271](https://github.com/paulpham157/sdf/issues/271)).
- `GET /api/summary`, `GET /api/snapshot`, and the report behind `GET /api/decisions/graph` reuse the summary computed for the current records snapshot and price catalog instead of reading and summarizing every row on each request. The snapshot is a `records_revision` generation, bumped once per insert and once per content scrub that rewrites a row, together with the greatest record id. The next request after an insert or a scrub matches a full recompute, including cumulative series. Git and GitHub outcomes are still attached on each request. The cache holds one report ([#273](https://github.com/paulpham157/sdf/issues/273)).
- `GET /api/summary`, `GET /api/snapshot`, and the report behind `GET /api/decisions/graph` on the UI port read the records table through a separate read-only connection (`store.OpenReadOnly`) instead of the receiver's writer connection, so a long UI read no longer holds the writer's mutex and blocks OTLP ingest. The JSON is unchanged; an in-memory store is still read through the writer ([#272](https://github.com/paulpham157/sdf/issues/272), [#328](https://github.com/paulpham157/sdf/pull/328)).

### CI/Build

- When a stable GitHub Release is published, open a pull request that sets `version`, `date-released`, and the release tag's commit in `CITATION.cff`. A `GITHUB_TOKEN` pull request does not start PR CI, so the job dispatches a fresh `base..head` gitleaks scan on `citation/vMAJOR.MINOR.PATCH` and waits for it. The ruleset check is named `gitleaks (full history)`; that scan is the pull request range, not every branch. Posting that status and merging happen only when the repository variable `CITATION_AUTOMERGE` is exactly `true` (off by default). Before turning it on, pin ruleset 26272056's check to GitHub Actions (integration 15368) or explicitly accept the unpinned-check risk. Pinning breaks the post-and-merge path unless a bypass is also configured, because a commit status is not a GitHub Actions check. `contents: write` is repo-wide; only the updater refuses the default branch. A `GITHUB_TOKEN` merge does not start Main CI or the push gitleaks job. An existing citation branch is reused only when its extra commits were created by this workflow, and a diverged or foreign branch fails the job instead of being force-pushed. Drafts, prereleases, and tags other than `vMAJOR.MINOR.PATCH` are skipped. The release tag is not moved. Cite this repository stays stale until the pull request merges ([#324](https://github.com/paulpham157/sdf/pull/324)).

## [0.1.0] — 2026-11-24

The first tagged release. Requires Go 1.26 or newer to build from source. Install with `go install github.com/paulpham157/sdf/cmd/sdf@v0.1.0` or with the prebuilt archives on [GitHub Releases](https://github.com/paulpham157/sdf/releases/tag/v0.1.0).

### Breaking changes

- **BREAKING:** `sdf decision link` now enforces endpoint kinds for relations that used to accept any kind. `implements` must run from a `session` or `commit` to a `decision` (a `decision` source, or a `session`/`commit` target, is refused); `validates` and `contradicts` must point to a `decision` (a `session` or `commit` target is refused); `constrains` must start from a `decision` (a `session` or `commit` source is refused). A refused link exits 1 with one line naming the rule and the end, for example `sdf decision link: implements links a session or commit to a decision: from is decision:a`. Rows an older sdf stored are kept and listed, count for the duplicate check, and drive no read-time field ([#278](https://github.com/paulpham157/sdf/pull/278)).

### Security

- Prompt and response content is now dropped before storing unless `sdf serve --store-content` or `SDF_STORE_CONTENT` is set. Tool and error text is dropped too ([#224](https://github.com/paulpham157/sdf/pull/224)).
- Validate `sdf init --host` / `--port` and quote shell snippets ([#195](https://github.com/paulpham157/sdf/pull/195)).
- Reject forged OTLP posts and rebound UI hosts ([#199](https://github.com/paulpham157/sdf/pull/199)).
- Harden `sdf verify` and the `sdf-verify` Action against a forged PASS: `go test` results come from a peer-checked harness, not stdout; designated file and vendor changes fail; each check runs in a pid namespace (or the verdict is ERROR `ISOLATION_UNAVAILABLE`); a data-dir-only or unpinned-ledger task is ERROR `TASK_UNTRUSTED` unless `--task-ref`, `--task-hash`, or `--expect-prefix` pins it; `--allow-unisolated` records `"isolation": "none"` and is never passed by the Action; and the Action step exits 0/1/3 to match the verdict. The go test harness channel is sealed, and `runtime/debug.WriteHeapDump` is flagged ([#209](https://github.com/paulpham157/sdf/pull/209), [7a84270](https://github.com/paulpham157/sdf/commit/7a8427004d0b71b8173bdd33073ff74e92ace700)).
- Create a missing telemetry or ledger database 0600, and a missing parent directory 0700, before SQLite opens it, so new `-wal`, `-shm`, and `-journal` files inherit mode 0600. On open, an existing database and its sidecars that group or others can access are tightened to owner-only (0644 becomes 0600; owner bits are kept), with one line naming the old mode; a chmod failure only warns and the open continues. An existing directory is never chmodded; sdf warns when group or others can write it, unless it is sticky ([#306](https://github.com/paulpham157/sdf/pull/306), fixes [#304](https://github.com/paulpham157/sdf/issues/304)).
